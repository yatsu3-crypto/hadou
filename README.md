# 覇道 部隊編成

信長の野望 覇道の部隊編成を、所持武将の中から提案する Web アプリ（スマホ向け）。

- 公開：GitHub Pages（`index.html`）
- データ：`data/busho.json`（武将）・`data/weights.json`（評価の重み）・`data/tags.json`（タグの語彙）
- 保存：ブラウザの localStorage のみ（`hadou_owned_v1`＝所持武将、`hadou_plan_v1`＝最後の提案条件、`hadou_tab_v1`＝最後に開いたタブ）
- 武将の画像・イラストは使わない

## 手元で開く

`index.html` をダブルクリックで開くと JSON を読み込めない。フォルダで次を実行して `http://localhost:8000/` を開く。

```
python3 -m http.server
```

## テスト

```
node tests/engine-test.js .
```

1部隊のときは全通り探索の結果と一致するか、混成（騎馬3・弓2）で重複がないか、時間がかかりすぎないかを確認する。

## 編成のルール（確認済み）

- 1部隊7人：大将1・副将2・与力4。能力の反映率は 大将＞副将＞与力
- 副将は左右1人ずつ、与力は左右2人ずつ。左＝攻撃時に発動、右＝防衛時に発動（`weights.json` の `slots`）
- 兵科：足軽・騎馬・弓・鉄砲・剣豪・忍者。適性は S/A/B/C
- 騎馬・足軽・剣豪＝前衛、弓・鉄砲＝後衛（`unit_role`）。忍者は未確定
- 混成：騎馬の部隊と弓の部隊を複数まとめて提案（既定は騎馬3・弓2）
- 大将時の兵科（`taisho_heika`）がある武将は、その兵科の部隊でしか大将にしない。空欄の武将は兵科適性で判定
- 縁はタグ（上杉家・平氏など）。同じ部隊に同じ縁タグの武将がそろうと発動。何人で発動するかは未確定（`en_min_members`、仮に2人）
- 同じ武将は複数の部隊に入れられない

## 評価のしくみ

編成の点 ＝ 部隊ごとの点の合計。部隊の点は次のとおり。

| 項目 | 計算 | 重み（weights.json） |
|---|---|---|
| 兵科適性 | 適性の点 × 位置の反映率 | `aptitude`・`position_weight` |
| 能力 | 統率・武勇・知略 ÷ `stat_scale` × 重み × 位置の反映率（政治・戦力は使わない） | `stat_weight`・`stat_scale` |
| 効果 | タグの重み × 出どころの重み × 位置の反映率 × 左右の効き × 兵科違いの倍率 × 役割の倍率 | `mode_tag_weight`・`source_weight`・`position_weight`・`side_weight`・`target_mismatch`・`role_tag_mult` |
| 縁 | 同じ縁タグの武将が `en_min_members` 人以上で加点。超えた1人ごとに追加 | `en_min_members`・`en_bonus`・`en_bonus_per_extra_member` |
| 相性 | 部隊内に効果タグの組み合わせがそろえば加点 | `synergy` |
| 減点 | 戦法の系統の重複、モードに必要な効果を持つ武将がいない | `penalty`・`required_roles` |

- 効果の評価に使うのは `tags` だけ。説明文（`desc`）は表示専用。
- 天賦（天賦値）は表示だけで、評価には使わない。
- 左右の効き：破壊・対人攻撃では左、防衛では右の枠の効果を重く見る（大将には掛からない）。
- 探索：ランダムな初期編成から入れ替えで点を上げる（山登り法）を `search.restarts` 回。2位・3位は「1位から1人または2人外したときの最善」も候補にし、上位の案と `search.min_diff` 人（既定2人）以上ちがう案を優先して出す。

## 武将データの書き方（data/busho.json、スキーマ v2）

```json
{
  "id": "uesugi_kenshin",              // 英字で固定。所持データはこの id で指す
  "name": "上杉謙信",
  "rarity": "UR",                      // tags.json の rarity のどれか
  "aptitude": { "足軽": "S", "騎馬": "S", "弓": "A", "鉄砲": "C", "剣豪": "A", "忍者": "B" },
  "taisho_heika": "騎馬",              // 大将時の兵科。この兵科の部隊でしか大将にしない。不明なら null
  "stats": { "統率": 1088, "武勇": 1100, "知略": 770, "政治": 670 },
  "power": 6648,                       // 戦力（表示のみ）
  "tenpu": 1100,                       // 天賦値（表示のみ）
  "skills": [ { "lv": 10, "name": "…", "desc": "…", "tags": ["ダメージ"] } ],   // Lv10/20/30/40 の4つ
  "kaiden": [ { "rank": 4, "name": "…", "desc": "…", "tags": ["破壊"] } ],      // ランク4〜7
  "senpo": { "name": "…", "lineage": "突撃", "desc": "…", "tags": ["ダメージ", "騎馬"] },
  "en": ["上杉家", "平氏", "軍神", "龍", "酒豪"],
  "season": 16,                        // 皆伝の情報のシーズン。meta.season と違うと警告
  "source": "…",
  "updated": "2026-10-31"
}
```

- `tags` には `tags.json` の `effect`（ダメージ・破壊・攻城・バフ・デバフ・回復・防御・妨害）と、兵科限定の効果なら `unit`（足軽・騎馬・弓・鉄砲・剣豪・忍者）を書く。
- 縁タグは自由に書いてよい。表記を武将どうしでそろえること（そろわないと発動しない）。
- 読み取れない・未確認の項目は `null`（一覧は `[]`）にして、項目名を `"missing": ["天賦", "技能"]` のように書く。画面の武将詳細と「データ」タブに表示される。
- ダミー武将は `"dummy": true`、id は `dummy_…`、名前に「（仮）」。実データが10人以上そろったら削除する予定。

## 実データの追加

1. 武将詳細画面のスクリーンショットを `screenshots/<武将名>/` に置く（リポジトリには入らない）
2. Claude Code に「screenshots の画像を取り込んで」と頼む（手順は `.claude/skills/busho-import/SKILL.md`）。読み取り結果が表で示されるので確認する
3. 確認後、`node tools/add-busho.js drafts/<id>.json` で追加される（`--check` で点検だけ）
- 入力ミス（語彙にないタグ、ほかに持つ武将がいない縁タグ、適性・能力値の書き漏れ、シーズン違い）は画面の「データ」タブに一覧で出る。
- 項目の設計は maker-mini.com の表を参考にしたが、データの自動取得はしない（作者の許可を取っていないため）。
